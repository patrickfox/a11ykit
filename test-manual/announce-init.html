Part 1 — Why is the first announcement dropped?

Two explanations fit the reports so far, and they need different fixes. Every sequence below uses the current implementation, unchanged.

Ordinality the region must be in the a11y tree BEFORE any content write predicts: the 2nd announcement speaks in every sequence aria-live change the AT re-registers when aria-live changes value. Each call does: manner -> 'off' -> manner. Same manner twice nets NO change once coalesced. predicts: same-manner sequences FAIL on the 2nd too

The deciding sequence is polite → polite. If its second announcement speaks, it is ordinality. If it stays silent while polite → assertive speaks, the aria-live toggle is the culprit — a worse bug than reported, since it would mean consecutive same-manner announcements usually fail.
